## Context

当前 `/` 是登录后的主应用页面（SPA 切换 看板/总览/汇报/版本）。甲方客户不应该经过用户选择登录流程，而是直接访问一个专属页面。同时总览页需要从"所有数据一把抓"调整为聚焦全局管理的精简面板。

### 现有架构

```
/ (App.tsx)
  ├── LoginPage（未登录）
  └── AppInner（已登录）
       ├── TopNav（导航栏）
       ├── KanbanBoard（看板）
       ├── Dashboard（总览）
       ├── Report（汇报）
       └── VersionPage（版本）
```

## Goals / Non-Goals

**Goals:**
- 新增 `/portal` 独立路由，无需认证即可访问
- Portal 展示甲方任务（`source === "jiafang"`）的核心进度
- Portal 支持评论功能（甲方反馈）
- Portal 支持版本切换
- 总览页移除甲方专属内容（甲方任务统计、完成进度条）
- 汇报页保留为 PM 的全局任务表格 + CSV 导出

**Non-Goals:**
- 不新增甲方用户账号（portal 无需登录）
- 不新增数据库表或 API
- 不修改看板页面

## Decisions

### 1. Portal 作为独立 Next.js 路由

**选择**: `src/app/portal/page.tsx`，独立的 page 组件，不走 `App.tsx` 的登录流程。

**考虑过的替代方案**:
- 在 App.tsx 内新增一个路由状态（如 `setView("portal")`）→ 拒绝，因为 portal 不应经过用户选择界面
- 创建独立子域名 → 拒绝，过于复杂

**理由**: Next.js App Router 天然支持独立路由，`/portal` 不需要共享 App.tsx 的登录态和导航栏。

### 2. Portal 数据获取方式

**选择**: 使用现有的 `GET /api/tasks` API，但新建一个 `GET /api/portal/tasks` 端点直接过滤 `source === "jiafang"`，无需 `x-user` header。

**考虑过的替代方案**:
- 复用 `/api/tasks` 接口 → 拒绝，现有接口需要用户认证且会按角色过滤
- Portal 页面直接 import db 函数 → 拒绝，服务端组件不适合直接操作客户端渲染的复杂交互

**理由**: Portal 无需用户认证，API 直接返回甲方任务，前端根据 `portalVersionId` 过滤。

### 3. Portal 页面结构

**选择**: 纯客户端组件（`"use client"`），与现有页面风格一致。

布局:
```
┌──────────┬────────────┐
│ 当前进行中 │ 整体进度     │
│ （列表）   │ （统计+进度环）│
├──────────┴────────────┤
│ 已交付（可折叠列表）      │
└───────────────────────┘
```

- 左上：当前进行中卡片（`status !== "done"` 的甲方任务列表，含标题、状态、负责人、截止日期）
- 右上：整体进度卡片（待交付/已交付计数 + 进度条）
- 底部：已交付折叠列表
- 顶部：版本选择器

### 4. 甲方评论功能

**选择**: Portal 页面允许在任务卡片上直接输入评论，调用现有 `POST /api/tasks/[id]/comments` 接口。发评论时使用固定用户名（如"甲方"）。

**理由**: 复用现有评论 API，不新增后端逻辑。

### 5. 总览页精简

移除以下区块：
- 甲方任务统计（移到 portal）
- 完成进度条（移到 portal）
- 导出汇报（移到汇报页或 remove）

保留：
- 统计卡片（总任务、完成率、进行中、已阻塞、已逾期）
- 任务清单表格
- 逾期任务预警
- 列分布
- 人员负载

### 6. 汇报页定位

汇报页保留为 PM 工具：全局任务表格 + CSV 导出。这是内部管理用途，与 portal 的甲方视角区分。

## Risks / Trade-offs

- **[风险] Portal 无认证可能导致公开暴露** → 不需要认证是设计意图，甲方通过 URL 访问，各项目可自行控制链接分发
- **[风险] 甲方评论身份固定为"甲方"** → 可接受，portal 的评论主要是给内部团队看的反馈
- **[取舍] 总览页去掉甲方内容后，PM 需切换到 portal 看甲方视图** → 两个页面各司其职，portal 专门给甲方看
