## Why

当前看板存在两个核心体验问题：

1. **数据实时性差** - 甲方通过 `/portal` 查看项目进度时，看到的是打开页面那一刻的快照。如果内部团队更新了任务状态，甲方必须手动刷新才能看到变化。这导致甲方对数据准确性产生怀疑，信任度下降。

2. **筛选功能不足** - 目前只有"来源"（甲方/内部/我的）和"优先级"筛选，缺少按日期范围和负责人筛选的能力。甲方经常问"张三负责的任务有哪些"、"这个月完成了哪些任务"，目前无法快速回答。

## What Changes

### 实时刷新
- 看板页面（KanbanBoard）每 30 秒自动轮询 `/api/tasks` 获取最新数据
- 甲方门户（Portal）每 15 秒自动轮询（甲方对实时性要求更高）
- 页面不可见时（`document.hidden`）暂停轮询，节省资源
- 数据变化时平滑更新，不打断用户当前操作

### 筛选增强
- 新增"负责人"筛选下拉框，列出所有 team member
- 新增"日期范围"筛选：今天、本周、本月、自定义范围
- 筛选状态持久化到 URL 参数，刷新页面后保留筛选条件
- 甲方门户同步支持新筛选项

## Capabilities

### New Capabilities
- `realtime-refresh`: 自动轮询刷新机制，支持可配置间隔、页面可见性检测、平滑数据更新
- `enhanced-filters`: 增强筛选系统，支持负责人筛选、日期范围筛选、URL 参数持久化

### Modified Capabilities
（无现有 spec 需要修改）

## Impact

### 前端组件
- `KanbanBoard.tsx` - 添加轮询逻辑、增强筛选 UI
- `Portal/page.tsx` - 添加轮询逻辑、增强筛选 UI
- `FilterBar/` - 新增负责人下拉、日期范围选择器

### API 路由
- `/api/tasks` - 现有接口，轮询会增加请求频率
- `/api/users/members` - 已有，用于获取负责人列表

### 性能考虑
- 轮询间隔需平衡实时性和服务器负载
- 考虑添加 `If-Modified-Since` 或 ETag 支持（可选优化）
- 大量任务时轮询响应体较大，可考虑增量更新（未来优化）
